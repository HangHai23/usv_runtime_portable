## 保留的Nano适配

- 两个ONNX模型保留，默认ONNX Runtime CPU推理；不使用Orin的TensorRT engine，不引入PyTorch依赖。
- Docker、JetPack4/Ubuntu18宿主与Ubuntu22/ROS2 Humble容器方案保持不变。
- 启动默认`DRY_RUN=true`，不会因为升级直接输出真实动力。I2C总线、串口、设备映射等部署设置仍需在目标设备核实。
- Mac来源IP继续使用安全占位`127.0.0.1`，请填现场Mac地址；不会强制照搬开发机的172.20.10.5。
- 原有导航平台路径、Nano设备配置和ONNX后端实现保留。

## 更新方法

先停止正在运行的控制系统，再在目标设备的仓库内运行：

```bash
git status --short
git pull --ff-only
```

有本地配置修改时先备份，不要使用强制重置。代码变化需要在原有ROS2 Humble运行环境（Nano通常是容器内）重新构建：

```bash
source /opt/ros/humble/setup.bash
cd ros2_ws
colcon build --symlink-install
source install/setup.bash
cd ..
./start_ball_mission.sh right
```

检查日志打印正确球类型及ONNX路径。改变球类型时修改`ball_type: red`或`multicolor`，重启整个系统；只修改`engine_path`不再是launch下的最终模型选择，需修改对应`red_engine_path/multicolor_engine_path`。

确认急停、遥控断联保护和手动接管正常后，才按原移植说明启用真实动力。本次更新已在开发机隔离ROS域验证，不代表在原版Nano硬件上完成水面实测。CPU推理帧率低于Orin时，需依据实际检测间隔调整新鲜度参数；不应为提高连续性而取消故障保护。持续无定位搜索没有避障能力，需现场人工监管。
